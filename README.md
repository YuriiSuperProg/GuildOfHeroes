### Проверка недопустимого урона

После `yaroslav.TakeDamage(-20);` здоровье Ярослава осталось прежним
(75), потому что метод отклоняет неположительный урон через `return;`.
Большой урон `artem.TakeDamage(200);` привёл здоровье Артёма к 0,

### Ответы на вопросы

**Почему при `yaroslav.TakeDamage(25);` не меняется здоровье Артёма и куда попадает 25?**

Метод экземпляра работает с полями того объекта, у которого вызван.
Получатель вызова — `yaroslav` (объект слева от точки), поэтому
`Health -= damage` меняет именно его поле. Артём в этом вызове не
участвует, его состояние остаётся прежним. Число 25 — аргумент,
который попадает в параметр `damage` метода `TakeDamage`.

**Чем отличаются `return;` в `TakeDamage` и `return Health > 0;` в `IsAlive`?**

`return;` в `TakeDamage` — ранний выход из `void`-метода: он ничего не
возвращает, просто прекращает выполнение при недопустимом уроне.
`return Health > 0;` в `IsAlive` возвращает значение типа `bool`:
сначала вычисляется выражение по текущему здоровью, затем результат
передаётся в место вызова.

**Как получить строку о герое, не печатая её сразу? Какая строка программы печатает её позже?**

Нужно вызвать метод и сохранить результат:

```csharp
string info = yaroslav.GetInfo();
```

## Собственный проект

Тема проекта: Автопарк

Главный класс: Car

Почему этот объект нужен программе:
Car описывает одну конкретную машину в автопарке. Программа должна
хранить данные о нескольких машинах одновременно, а класс позволяет
держать все характеристики одной машины вместе и создавать сколько
угодно независимых объектов с собственным состоянием.

Какие данные хранит объект:

- Brand — марка машины (string)
- Model — модель (string)
- EngineVolume — объём двигателя в литрах (double)
- Year — год выпуска (int)
- Color — цвет (string)
- IsAvailable — доступна ли машина (bool)

Какие значения задаются через конструктор:
Brand, Model, Year, Color, EngineVolume — эти данные уникальны
для каждой машины и не могут быть придуманы программой, поэтому
передаются при создании объекта.

Какие значения можно задавать автоматически:
IsAvailable = true — новая машина при добавлении в автопарк
по умолчанию доступна для использования, поэтому это значение
назначается внутри конструктора без параметра.

### Дополнительное задание

Автоматически задаваемое значение: IsAvailable = true.

Почему: машина, только что добавленная в автопарк, по умолчанию
свободна. Передавать true при каждом создании объекта избыточно,
поэтому значение устанавливается внутри конструктора. Если машину
забронируют, поле можно изменить позже: `bmw.IsAvailable = false;`

Проверка: при создании объектов bmw, lada и tesla поле IsAvailable
равно true — это видно в выводе программы.

Что делает: меняет цвет машины; отклоняет попытку перекрасить

Что делает: увеличивает пробег на `km`; отклоняет неположительное

над его собственными полями. Они не имеют смысла для героя или
товара и не копируют поведение `Hero`.

## Практическая работа №3

### Защищённое состояние класса Car

Почему методы ПР №2 не защищали от прямой записи в поле:
поле `Mileage` было открытым (`public int Mileage;`), поэтому из
`Program.cs` можно было написать `bmw.Mileage = -500;` и обойти
проверку `km <= 0` внутри `AddMileage`. Метод не вызывался — поле
менялось напрямую.

Чем отличаются get, set и private set:
- `get` — выполняется при чтении значения;
- `set` — при присваивании;
- `private set` — присваивать может только код внутри класса `Car`,
  а читать снаружи по-прежнему можно.

Где проверяется начальное здоровье (пробег):
в конструкторе: `Mileage = mileage; if (Mileage < 0) Mileage = 0;`
Отрицательный начальный пробег приводится к 0.

Почему в конструкторе достаточно `Mileage = mileage;`:
конструктор находится внутри `Car`, поэтому `private set` ему
разрешает запись. Но `private set` не проверяет число — поэтому
рядом стоит явная проверка `if (Mileage < 0)`.

### Проверки

Конструктор: входные значения и полученные Mileage:
- `new Car("ГАЗ", "Газель", 2.8, 2019, "Белый", 1000)` → Mileage = 1000;
- `new Car("КАМАЗ", "5490", 12.0, 2021, "Синий", -500)` → Mileage = 0.

Допустимое и недопустимое действие:
- `gazelle.AddMileage(250)` → 1250 км;
- `gazelle.AddMileage(-100)` → отклонено, остаётся 1250 км.

Какая внешняя запись не скомпилировалась и почему:
`gazelle.Mileage = 999;` → ошибка компиляции **CS0272**, потому что
setter объявлен как `private set` и недоступен из `Program.cs`.

### Итог

Правило `Mileage >= 0` соблюдается:
- при создании (проверка в конструкторе);
- после каждого вызова `AddMileage` (проверка `km <= 0`);
- внешняя запись запрещена (`private set`).
